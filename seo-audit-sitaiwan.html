網站概況 網站概況 — 社會創新平台 ▶
類型：政府出版入口網 主管機關：經濟部中小及新創企業署 語言：繁體中文（主）+ 英文 鏡像網域：si.taiwan.gov.tw 網域：sme.gov.tw（高權威）

社會創新平台由經濟部中小及新創企業署（SMESA）運營，是台灣社會創新組織的全國性資料庫與資源中心，與聯合國永續發展目標（SDGs）接軌。

網站架構：5 個主選單群組、21 個靜態頁面，加上組織（/Home/Org?Fid={id}）與活動（/Home/activity/{id}）的程式化頁面。平台採用 JavaScript SPA 框架，伺服器端渲染（SSR）有缺口。

核心發現：主網域 startup.sme.gov.tw/sitaiwan/ 對所有爬蟲請求返回 HTTP 403，而鏡像網域 si.taiwan.gov.tw 可部分提供內容。這個雙網域問題是本平台最嚴重的 SEO 漏洞。

嚴重 主網域對所有機器人返回 HTTP 403 — Googlebot 無法爬取網站 ▶

觀察：startup.sme.gov.tw/sitaiwan/ 上的每個 URL 對自動化請求都返回 HTTP 403。包括首頁、所有子頁面及所有程式化頁面，Googlebot 被完全封鎖。

影響：即使頁面曾被快取或從鏡像網域索引，Google 也無法重新驗證內容、發現新頁面或更新排名。長期下去，所有已索引頁面將從搜尋結果中消失。

根本原因推測：伺服器可能套用了 User-Agent 過濾或 IP 範圍封鎖，可能是防火牆規則、WAF 政策，或原本設計封鎖惡意機器人的設定誤傷了 Googlebot。

修復：在 WAF/防火牆規則中將 Googlebot 的 User-Agent 加入白名單 驗證：修復後在 Search Console 使用「以 Google 身分擷取」 成功指標：GSC 顯示首頁爬取成功
嚴重 robots.txt 遺失 (404) — 未宣告爬取政策 ▶

https://startup.sme.gov.tw/sitaiwan/robots.txt 返回 HTTP 404。沒有 robots.txt，爬蟲在路徑層級沒有任何爬取政策可遵循，加上網域層級的 403，爬蟲完全無從得知哪些內容可爬取。

修復：在網域根目錄（或 /sitaiwan/ 路徑層級）建立 /robots.txt，加入明確的 User-agent: *、Allow: / 指令，以及指向 XML Sitemap 的 Sitemap: 指令。

嚴重 無 XML Sitemap — Googlebot 無法發現所有頁面 ▶

/sitaiwan/sitemap.xml 返回 403。目前只有 /sitaiwan/sitemap 的 HTML 網站地圖頁面，列出 21 個靜態 URL，但這個 HTML 網站地圖無法被 Googlebot 以機器方式讀取。

更嚴重的是，程式化頁面（/Home/Org?Fid=* 的組織頁面與 /Home/activity/* 的活動頁面）完全沒有被列入任何機器可讀的格式，這可能代表數百乃至數千個 Google 無法發現的頁面。

修復：建立包含兩個子 Sitemap 的 Sitemap Index：一個針對靜態頁面，一個針對程式化頁面。加入 <lastmod> 和 <changefreq>，在 Google Search Console 登錄，並在 robots.txt 加入 Sitemap: 指令。

嚴重 JavaScript SPA 純前端渲染 — 內容對爬蟲不可見 ▶

列表頁面（/Home/org_list、/Home/activity/list）返回空白 HTML，組織資料庫和活動列表完全透過 JavaScript 客戶端載入。原始碼中可見未渲染的模板語法 {{ language == 'en' ? 'Home' : '回首頁' }}，確認框架（可能是 Vue.js 或 Angular）未對這些字串執行 SSR。

影響：Googlebot 看到的是空白列表頁面，平台絕大多數可索引內容（數千個組織檔案和活動頁面）對搜尋引擎可能完全不可見。

修復：為所有公開頁面實作伺服器端渲染（SSR）或靜態網站生成（SSG）。至少使用動態渲染（預先渲染）向 Googlebot 提供已渲染的 HTML。SSR 修復是所有頁面 SEO 優化能發揮效果的前提條件。

依賴關係：必須先修復，其他所有 SEO 工作才能發揮效果
嚴重 相同內容分佈在兩個網域且無 canonical — 嚴重的重複內容風險 ▶

相同的平台內容同時出現在 startup.sme.gov.tw/sitaiwan/ 和 si.taiwan.gov.tw/，兩個網域都未設置 canonical 標籤指向權威版本。Google 可能同時索引兩者、分散連結權益，並因重複內容而降低兩者的排名。

修復：確定一個正式網域（建議使用 startup.sme.gov.tw/sitaiwan/，因其位於主要政府網域下）。從鏡像網域實施 301 轉址，或在鏡像網域每個頁面加入 <link rel="canonical"> 指向正式網域對應的 URL。

高 導覽列章節標題不可爬取 — javascript:; 連結 ▶

5 個主選單群組標題（掌握資源、影響力變現、國際合作、BP 獎項申請、社創資料庫）使用 href="javascript:;"，不可被 Googlebot 爬取，也無法提供連結權益或爬取訊號。

修復：將每個章節標題指向其主要子頁面，或實作連結至真實 URL 的正確下拉選單。例如「掌握資源」應連結到其最重要的子頁面。

中 僅建議桌面瀏覽器 — 未宣告行動版優化 ▶

網站頁尾明確建議「使用桌上型電腦 Google Chrome 瀏覽，解析度 1024×768 以上」。Google 採用行動優先索引——若網站不支援行動裝置，排名將受到懲罰。這個建議說明網站並非為行動用戶設計。

修復：對所有頁面類型進行行動版響應式審查。確保點擊目標達到最小 48×48px，文字無需縮放即可閱讀，內容在 390px 寬度的視窗不溢出。移除頁尾的桌面版建議。

嚴重 所有頁面均無 meta description — 搜尋摘要依賴 Google 自動生成 ▶

平台上沒有任何一個頁面設有 <meta name="description"> 標籤，包括首頁、列表頁、活動頁和組織頁面均已確認缺少。Google 將從頁面內容自動生成摘要，通常較不吸引人，且可能顯示無關文字。

修復：為所有靜態頁面撰寫獨特的 meta description（150–160 字元）。程式化頁面使用模板，例如組織頁面：{org_name}是台灣社會創新組織，專注於{sdg_category}。了解其社會影響力、採購資訊與聯絡方式。

影響頁面：所有 21+ 靜態頁面及所有程式化頁面 工作量：模板化——SSR 修復後每頁成本極低
高 通用頁面標題 — 每個頁面都是「社會創新平台 | Social Innovation - [Section]」 ▶

所有頁面遵循相同的標題模式：社會創新平台 | Social Innovation - [章節名稱]。例如：社會創新平台 | Social Innovation - 2025 台灣 AI 產業年會。雖然包含活動名稱，但缺少目標關鍵字、地理修飾語或能提升 SERP 點擊率的行動導向語言。

修復：將標題結構反轉，以最具體、關鍵字豐富的詞語開頭。活動頁面：2025 台灣 AI 產業年會 | 社會創新平台活動；組織頁面：{組織名稱} - 社會創新組織 | 社創平台；首頁：台灣社會創新平台 - SDGs 社創組織資料庫 | SMESA。

高 所有頁面均無 canonical 標籤 — 重複 URL 風險未受管控 ▶

沒有任何頁面設置 <link rel="canonical"> 標籤。這在以下情況特別危險：（1）雙網域問題；（2）如 /Home/News?Fid=156 等帶有參數的 URL 可能產生變體；（3）任何尾部斜線或 www/non-www 變體。

修復：為所有頁面加入自我參照 canonical 標籤。帶有查詢字串的程式化頁面，canonical 指向乾淨 URL 版本。這是框架層級的修復，一次應用到所有頁面模板。

高 無 Open Graph 或 Twitter Card 標籤 — 社群分享樣貌不佳 ▶

所有頁面均無 og:title、og:description、og:image 或 Twitter Card meta 標籤。當平台連結被分享到社群媒體（Facebook、LINE、Twitter/X）時，不會生成預覽卡片，只顯示純文字 URL。

修復：為所有頁面加入 Open Graph 標籤。活動和組織頁面使用活動橫幅或組織 Logo 作為 og:image。最低要求：og:title、og:description、og:image、og:url、og:type、og:locale（設為 zh_TW），若有英文版加入 og:locale:alternate。

高 所有頁面均無 HTML lang 屬性 — 缺少無障礙與 SEO 訊號 ▶

<html> 元素沒有 lang 屬性，這既是無障礙問題（螢幕閱讀器無法推斷語言），也是 SEO 訊號——Google 使用 lang 屬性了解內容語言以進行區域定向。

修復：在中文頁面的 <html> 元素加入 lang="zh-TW"，英文頁面加入 lang="en"。這是框架層級的修復。

中 關鍵圖片缺少 alt 文字 — 首頁說明圖和網站 Logo ▶

首頁「什麼是社會創新？」的說明圖片沒有 alt 文字。網站 Logo 在某些情境下也缺乏有意義的 alt 文字。活動橫幅圖片使用檔名（1735531105438.jpg）而非描述性文字作為 alt。

修復：為所有有意義的圖片加入描述性 alt 文字。裝飾性圖片使用 alt=""。活動橫幅使用活動名稱和日期。Logo 使用「社會創新平台 - 經濟部中小及新創企業署」。SDG 說明圖描述視覺化內容所呈現的資訊。

中 無麵包屑導覽 — 對 Google 傳達淺層網站結構訊號 ▶

網站使用扁平的工具導覽（回首頁 → 新手專區 → 網站導覽），深層頁面沒有情境麵包屑。活動頁面（如 /Home/activity/3280）沒有麵包屑顯示「首頁 → 活動看板 → 2025 AI 論壇」，對 UX 和 SEO 都是錯失的機會。

修復：為所有分類和詳情頁面加入麵包屑導覽，搭配 BreadcrumbList JSON-LD（見結構化資料章節）。這也能啟用 Google 的麵包屑 SERP 功能。

高 首頁統計數字全部顯示零 — 內容在渲染前未載入 ▶

首頁「重點數據」區塊所有統計數字均顯示 0：社會創新組織（0）、合作企業（0）、就業人口、採購金額（0）。這表示資料透過 JavaScript 非同步載入，未在伺服器端渲染。

影響：這些數字是展示平台規模的核心 E-E-A-T 訊號。Google 爬取頁面時看到的是零，削弱了可信度訊號；使用者初次載入看到零也會失去信任。

修復：在伺服器端預先渲染這些統計數字。至少將最新數字直接嵌入 HTML 作為備用，JavaScript 再進行更新。HTML 原始碼中這些數字絕對不能是零。

高 列表頁面段落內容重複 — 偵測到逐字重複 ▶

在組織資料庫頁面和活動列表頁面，合作企業說明段落和社會創新組織說明段落各出現兩次，完全一字不差。這造成頁面內重複內容，徒增內容篇幅卻無附加價值。

修復：審查所有模板元件是否有重複渲染的情況，原因很可能是某個元件在頁面模板中被引入了兩次。移除重複的實例。

中 重要政策文件僅提供 PDF — 內容對搜尋引擎不可見 ▶

社創方案 2.0 及其英文版僅提供可下載的 PDF，雖然 Google 可以索引 PDF，但其 SEO 效果遠不如網頁。這份內容詳述台灣國家社會創新策略，對研究人員、記者和國際組織具有很高的搜尋潛力。

社創方案2.0摘要.pdf Social_Innovation_Action_Plan_2.0_Summary.pdf

修復：為這些文件建立帶有適當標題、章節和錨點連結的網頁版本，保留 PDF 下載作為次要選項。網頁版本將為這些文件所涉及的長尾查詢贏得排名。

中 SDGs 診斷測驗需要登入 — 封閉內容阻礙自然搜尋流量 ▶

「SDGs 社創小將診斷測驗」需要會員登入。這個受歡迎的互動工具對搜尋引擎和尚未註冊的新訪客完全不可見，是自然流量獲取的重大損失。

修復：為診斷測驗建立公開預覽或著陸頁面，包含足夠的 SEO 內容以在 SDG 相關查詢中排名。測驗本身可以繼續設門檻，但入口頁面應可被索引並有吸引人的 meta 標籤。

低 已結束活動仍被索引，缺乏明確的封存策略 ▶

已過去的活動頁面（標記「已結束」）仍然完全被索引，例如 2025 年 AI 產業年會活動頁面仍可存取。保留過去活動是合理的，但這些頁面缺乏明確的常青內容策略。

修復：在過去活動頁面加入結構化資料標記（使用 eventStatus: EventScheduled 加上過去日期，而非 EventCancelled）。考慮在過去活動頁面加入「相關即將到來的活動」區塊，以降低跳出率並增加內部連結價值。

結構化資料
5 / 100
嚴重 整個網站無結構化資料 — 任何地方都找不到 JSON-LD ▶

平台上沒有任何頁面實作任何形式的結構化資料（JSON-LD、Microdata 或 RDFa）。對於擁有豐富、結構化內容類型的政府平台而言，這是重大的錯失機會。

依頁面類型建議的 Schema 實作：

首頁：Organization、WebSite、GovernmentOrganization 活動頁面：Event（含 EventScheduled、startDate、endDate、location） 組織頁面：Organization 或 LocalBusiness 子類型 所有頁面：BreadcrumbList、WebPage

活動頁面 JSON-LD 範例：

{"@type":"Event","name":"2025台灣AI產業年會","startDate":"2025-01-22","location":{"@type":"Place","address":{"@type":"PostalAddress","addressLocality":"台北市","streetAddress":"羅斯福路四段85號"}},"organizer":{"@type":"Organization","name":"台灣人工智慧實驗室"},"eventStatus":"https://schema.org/EventScheduled"}

實作 Event Schema 可在 SERP 顯示 Google 活動豐富結果，是這類平台最直接的流量驅動器。

高 未宣告政府組織實體 — 錯失 Google 知識面板機會 ▶

平台沒有 GovernmentOrganization 或 Organization Schema 宣告發布者身份（SMESA / 經濟部中小及新創企業署）。沒有這個宣告，Google 無法確信地將平台與其組織實體關聯，錯失潛在的知識面板。

修復：在首頁加入：

{"@type":"GovernmentOrganization","name":"經濟部中小及新創企業署","alternateName":"SMESA","url":"https://startup.sme.gov.tw/","parentOrganization":{"@type":"GovernmentOrganization","name":"經濟部"},"contactPoint":{"@type":"ContactPoint","telephone":"+886-2-2586-5000","email":"sitaiwan@sme.gov.tw"},"sameAs":["https://www.sme.gov.tw/"]}

高 BreadcrumbList Schema 缺失 — 無法使用麵包屑 SERP 功能 ▶

不存在 BreadcrumbList 結構化資料。加上缺乏可見的麵包屑導覽，Google 無法在搜尋結果中顯示麵包屑，而 SERP 中的麵包屑透過展示內容層級結構可提升點擊率。

修復：在所有分類和詳情頁面實作 BreadcrumbList JSON-LD，與視覺麵包屑導覽同步。活動頁面範例：首頁 → 活動看板 → [活動名稱]。

AI 搜尋整備度 (GEO)
10 / 100
嚴重 AI 爬蟲遭封鎖 — Googlebot 及所有 AI 代理程式無法存取任何內容 ▶

封鎖 Googlebot 的相同 HTTP 403 也封鎖了 AI 內容爬蟲（GPTBot、ClaudeBot、Applebot、PerplexityBot 等），這意味著在有關台灣社會創新、SDGs 和社會企業的 AI 生成答案中，本平台內容完全缺席。

影響：當使用者向 ChatGPT、Perplexity、Google AI Overviews 或 Claude 詢問「台灣社會創新」或「Taiwan social enterprise organizations」時，本平台不會出現在引用來源中。

修復：解決 403 問題後，在 robots.txt 中明確允許有益的 AI 爬蟲，只封鎖具攻擊性或未知的機器人。

高 無 llms.txt 檔案 — 平台無法向 AI 代理程式宣告自身 ▶

網域上不存在 /llms.txt。這個新興標準讓 AI 代理程式了解網站的內容性質及如何適當使用其內容。對於希望被 AI 系統引用的政府平台，這是投入少、訊號價值高的改善。

修復：建立 https://startup.sme.gov.tw/llms.txt，簡要描述平台、資料類型、預期用途及授權聯絡方式。範例：

# Social Innovation Platform — Taiwan
社會創新平台 is operated by SMESA (Ministry of Economic Affairs, Taiwan). It provides a database of social innovation organizations, events, and resources aligned with the UN SDGs.

## Organization database
Detailed profiles of 1000+ social innovation organizations in Taiwan.

## Allowed uses
Citation, research, journalism, non-commercial use.

中 無 Markdown 交付端點 — AI 代理程式偏好結構化文字格式 ▶

平台僅提供 HTML（或因 403 完全無內容）。偏好乾淨 Markdown 或 JSON 格式的 AI 爬蟲無法有效處理本網站。

修復：建立 /llms-full.txt，或在關鍵頁面（組織檔案、政策文件）實作 Accept: text/markdown 內容協商。或者，為組織資料庫公開 JSON API 端點，供 AI 代理程式參考。

多語系 / Hreflang
10 / 100
高 未實作 hreflang — 雙語網站在英文搜尋結果中不可見 ▶

平台同時擁有中文（zh-TW）和英文內容（由英文 PDF 下載和雙語導覽標籤確認），但所有頁面均無 hreflang 標籤。沒有 hreflang，Google 對中英文搜尋者提供相同的 URL，英文版可能在英文搜尋結果中被壓制。

修復：確認是否存在平行英文 URL 結構（例如 /sitaiwan/en/）。若存在，在所有雙語頁面實作 hreflang：

<link rel="alternate" hreflang="zh-TW" href="https://startup.sme.gov.tw/sitaiwan/Home/activity/3280">
<link rel="alternate" hreflang="en" href="https://startup.sme.gov.tw/sitaiwan/en/Home/activity/3280">
<link rel="alternate" hreflang="x-default" href="https://startup.sme.gov.tw/sitaiwan/Home/activity/3280">

若不存在平行英文 URL 結構，則建立一個。平台的國際抱負（APSI Summit、海外拓展）使英文 SEO 具有重要意義。

中 Vue/Angular 模板字串在 HTML 原始碼中可見 — 語言在渲染時未解析 ▶

導覽標籤包含未渲染的模板表達式：{{ language == 'en' ? 'Home' : '回首頁' }}，在頁面原始碼中以原始 JavaScript 模板語法可見，表示語言偵測邏輯在客戶端執行，而非在伺服器或 SSR 階段解析。

影響：爬蟲將模板語法視為字面文字內容，這使爬取的文字被程式碼殘留污染，並向 Google 傳遞網站內容不可靠的訊號。

修復：確保所有語言條件字串在 SSR 階段、HTML 傳送給客戶端之前完成解析。模板表達式絕不應出現在已交付的 HTML 中。

低 新聞版塊使用查詢字串 URL — /Home/News?Fid=156 不利 SEO ▶

新聞分類的導覽項目使用 /Home/News?Fid=156 而非乾淨 URL（如 /Home/news/social-innovation）。查詢字串 URL 雖可爬取，但 SEO 友善度較低，且 canonical 管理較困難。

修復：盡可能將查詢字串參數映射到乾淨 URL 路徑，在伺服器端實作 URL 改寫。若乾淨 URL 不可行，確保 canonical 標籤明確處理每個查詢字串變體。
