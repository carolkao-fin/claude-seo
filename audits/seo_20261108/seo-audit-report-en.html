Site Profile Site Overview — Social Innovation Platform ▶
Type: Government Publisher Portal Operator: SMESA / MOEA Taiwan Language: Chinese (primary) + English Mirror: si.taiwan.gov.tw Domain: sme.gov.tw (high authority)

The Social Innovation Platform (社會創新平台) is operated by Taiwan's SMESA under the Ministry of Economic Affairs. It serves as a national directory and resource hub for social innovation organizations, aligned with the UN SDGs.

Architecture: 5 main navigation groups, 21 static pages, plus programmatic pages for organizations (/Home/Org?Fid={id}) and activities (/Home/activity/{id}). The platform uses a JavaScript SPA framework with SSR gaps.

Key observation: The main domain startup.sme.gov.tw/sitaiwan/ returns HTTP 403 for all crawler requests, while the mirror si.taiwan.gov.tw partially serves content. This domain split is the most critical SEO vulnerability.

⚙️
Technical SEO
15 / 100
Critical Main domain returns HTTP 403 for all bots — Googlebot cannot crawl the site ▶

Observation: Every URL on startup.sme.gov.tw/sitaiwan/ returns HTTP 403 Forbidden to automated requests — homepage, all section pages, and all programmatic pages. Googlebot is completely blocked.

Impact: Even if pages were indexed from cached state or the mirror domain, Google cannot re-verify content, discover new pages, or update rankings. Over time, all indexed pages will be dropped from search results.

Root cause: The server likely applies User-Agent filtering or IP-range blocking — an infrastructure firewall rule, WAF policy, or bot-blocking config that was misconfigured to also block Googlebot.

Fix: Whitelist Googlebot User-Agent in WAF/firewall rules Verify: Use "Inspect URL" in Google Search Console after fix Success signal: GSC shows successful crawl of homepage
Critical robots.txt missing (404) — no crawl policy declared ▶

https://startup.sme.gov.tw/sitaiwan/robots.txt returns HTTP 404. Without robots.txt, there is no crawl policy at the path level. Combined with the domain-level 403, crawlers receive no guidance on what is or is not crawlable.

Fix: Create /robots.txt at the domain root with User-agent: *, Allow: /, and a Sitemap: directive pointing to the XML sitemap.

Critical No XML sitemap — Googlebot cannot discover all pages ▶

/sitaiwan/sitemap.xml returns 403. Only an HTML sitemap at /sitaiwan/sitemap exists, listing 21 static URLs — not machine-readable by Googlebot for sitemap purposes.

Programmatic pages (organizations at /Home/Org?Fid=* and activities at /Home/activity/*) are not listed anywhere machine-readable. These likely represent hundreds or thousands of pages Google cannot discover.

Fix: Generate a sitemap index with two child sitemaps: static pages and programmatic pages. Include <lastmod> and <changefreq>. Register in GSC and add Sitemap: to robots.txt.

Critical JavaScript SPA with client-side rendering — content invisible to crawlers ▶

Listing pages (/Home/org_list, /Home/activity/list) return bare HTML — the org database and activity list are loaded entirely client-side via JS. Unrendered template syntax like {{ language == 'en' ? 'Home' : '回首頁' }} in source confirms the framework (likely Vue.js or Angular) is not SSR-rendering these strings.

Impact: Googlebot sees empty listing pages. The vast majority of indexable content (thousands of org profiles and event pages) may be invisible to search engines.

Fix: Implement SSR or SSG for all public pages. At minimum, use dynamic rendering (pre-rendering) to serve rendered HTML to Googlebot. SSR is the prerequisite for all on-page SEO improvements to have effect.

Dependency: Must fix before any other SEO work has effect
Critical Duplicate site across two domains with no canonical — severe duplicate content risk ▶

The same platform content is served on both startup.sme.gov.tw/sitaiwan/ and si.taiwan.gov.tw/. Neither domain sets canonical tags pointing to the authoritative version. Google may index both, split link equity, and demote both for duplicate content.

Fix: Choose one canonical domain (recommend startup.sme.gov.tw/sitaiwan/). Implement 301 redirects from the mirror, OR add <link rel="canonical"> on every mirror page pointing to the canonical URL.

High Non-crawlable section headers in navigation — javascript:; links ▶

The 5 main navigation group headers use href="javascript:;". These are not crawlable by Googlebot and provide no link equity or crawl signal.

Fix: Point each section header to its primary child page, or implement a proper dropdown that links to real URLs.

Medium Desktop-only browser recommendation — no mobile optimization declared ▶

The site footer explicitly recommends "desktop Google Chrome at 1024×768 or higher." Google uses mobile-first indexing — if the site is not mobile-friendly, rankings are penalized. This signals the site was not designed for mobile users.

Fix: Conduct a mobile responsiveness audit across all page types. Ensure tap targets meet 48×48px minimums, text is readable without zooming, and content does not overflow on 390px viewports. Remove the desktop-only recommendation.

Critical Zero meta descriptions across all pages — search snippets rely on Google auto-generation ▶

Not a single page on the platform has a <meta name="description"> tag — confirmed across homepage, listing pages, activity pages, and organization pages. Google auto-generates snippets, which are typically less compelling and may show irrelevant text.

Fix: Write unique meta descriptions for all static pages (150–160 chars). For programmatic pages use a template, e.g. for org pages: {org_name} is a Taiwan social innovation organization focused on {sdg_category}. Learn about their social impact, procurement, and contact info.

Pages affected: All 21+ static + all programmatic pages Effort: Templated — low per-page cost once SSR is fixed
High Generic page titles — "社會創新平台 | Social Innovation - [Section]" on every page ▶

All pages follow the title pattern 社會創新平台 | Social Innovation - [Section]. While the event name is included, the title lacks target keywords, geographic modifiers, or action language that would improve SERP CTR.

Fix: Reverse the title structure to lead with the most specific, keyword-rich term. Event pages: 2025 台灣 AI 產業年會 | Social Innovation Platform. Org pages: {Org Name} — Social Innovation Org | SMESA. Homepage: Taiwan Social Innovation Platform — SDGs Org Database | SMESA.

High No canonical tags on any page — duplicate URL risk unmanaged ▶

No page sets a <link rel="canonical"> tag. This is especially problematic given: (1) the dual-domain issue, (2) query string URLs like /Home/News?Fid=156 that could generate parameter variants, and (3) any trailing-slash or www/non-www variants.

Fix: Add self-referencing canonical tags to all pages. For programmatic pages with query strings, canonicalize to the clean URL version. This is a template-level fix applied once to the page framework.

High No Open Graph or Twitter Card tags — poor link sharing appearance ▶

No pages have og:title, og:description, og:image, or Twitter Card meta tags. When links are shared on social media (Facebook, LINE, Twitter/X), no preview card is generated — only a plain URL appears.

Fix: Add Open Graph tags to all pages. Use event banners or org logos as og:image. Minimum set: og:title, og:description, og:image, og:url, og:type, og:locale (set to zh_TW). Include og:locale:alternate for English pages.

High No HTML lang attribute on any page — accessibility and SEO signal missing ▶

The <html> element has no lang attribute. This is both an accessibility issue (screen readers cannot infer language) and an SEO signal — Google uses lang to understand content language for regional targeting.

Fix: Add lang="zh-TW" to the <html> element on Chinese pages and lang="en" on English pages. This is a framework-level fix.

Medium Missing alt text on key images — homepage explainer image and site logo ▶

The homepage "What is social innovation?" explainer image has no alt text. The site logo also lacks meaningful alt text in some contexts. Event banner images use filenames (1735531105438.jpg) instead of descriptive text.

Fix: Add descriptive alt text to all meaningful images. Decorative images use alt="". For event banners, use the event name and date. For the logo, use "Social Innovation Platform — SMESA". For the SDG explainer image, describe what the visualization shows.

Medium No breadcrumb navigation — shallow site structure signal to Google ▶

The site uses a flat utility navigation with no contextual breadcrumbs on deep pages. For activity pages like /Home/activity/3280, there is no breadcrumb showing "Home → Activities → 2025 AI Forum". This is a missed opportunity for both UX and SEO.

Fix: Add breadcrumb navigation to all section and detail pages. Pair with BreadcrumbList JSON-LD (see Schema section). This also enables Google breadcrumb SERP features.

High Homepage statistics showing all zeros — content not loading before render ▶

The homepage Key Figures section shows 0 for all statistics. Data loads asynchronously via JavaScript and was not rendered server-side.

Impact: These numbers are core E-E-A-T signals showing platform scale. Google sees zeros, undermining credibility. Users seeing zeros on first load lose trust.

Fix: Pre-render these statistics server-side. Embed the latest figures in the HTML as a fallback that JavaScript can then refresh. These numbers should never be zero in the HTML source.

High Duplicate paragraph content on listing pages — verbatim repetition detected ▶

On organization database and activity list pages, description paragraphs each appear twice verbatim. This creates on-page duplicate content and inflates content length without adding value.

Fix: Audit all template components for duplicate rendering. The likely cause is a component included twice in the page template. Remove duplicate instances.

Medium Key policy documents only available as PDFs — content invisible to search ▶

The Social Innovation Action Plan 2.0 and its English version are only available as PDFs. PDFs perform significantly worse than web pages in SEO. This content — detailing Taiwan national social innovation strategy — has high search potential for researchers, journalists, and international organizations.

社創方案2.0摘要.pdf Social_Innovation_Action_Plan_2.0_Summary.pdf

Fix: Create web page versions of these documents with proper headings, sections, and anchor links. Keep the PDF download as a secondary option. The web page version will rank for long-tail queries.

Medium SDGs diagnostic test requires login — gated content blocks organic discovery ▶

The SDGs diagnostic test requires member login. This popular interactive tool is completely invisible to search engines and unregistered visitors — a significant missed opportunity for organic acquisition.

Fix: Create a public landing page for the diagnostic test with enough SEO content to rank for SDG-related queries. The test itself can remain gated, but the entry page should be indexable with compelling meta tags.

Low Ended events remain indexed without clear archival strategy ▶

Past event pages (marked ended) remain fully indexed. While keeping past events is legitimate, there is no clear evergreen content strategy for these pages.

Fix: Add structured data to past event pages using eventStatus: EventScheduled with the past date. Add a "Related upcoming events" section to past event pages to reduce bounce and add internal linking value.

Schema & Structured Data
5 / 100
Critical Zero structured data on the entire site — no JSON-LD found anywhere ▶

Not a single page implements any form of structured data (JSON-LD, Microdata, or RDFa). This is a significant missed opportunity for a government platform with rich, structured content types.

Recommended schema implementations by page type:

Homepage: Organization, WebSite, GovernmentOrganization Activity pages: Event (EventScheduled, startDate, endDate, location) Org pages: Organization or LocalBusiness subtypes All pages: BreadcrumbList, WebPage

Example for event pages (JSON-LD):

{"@type":"Event","name":"2025台灣AI產業年會","startDate":"2025-01-22","location":{"@type":"Place","address":{"@type":"PostalAddress","addressLocality":"台北市","streetAddress":"羅斯福路四段85號"}},"organizer":{"@type":"Organization","name":"台灣人工智慧實驗室"},"eventStatus":"https://schema.org/EventScheduled"}

Implementing Event schema enables Google Event rich results in SERP — a direct traffic driver for this platform type.

High Government organization entity not declared — Google Knowledge Panel opportunity missed ▶

The platform has no GovernmentOrganization or Organization schema declaring publisher identity. Without this, Google cannot confidently associate the platform with its entity, missing a potential Knowledge Panel.

Fix: Add on the homepage:

{"@type":"GovernmentOrganization","name":"經濟部中小及新創企業署","alternateName":"SMESA","url":"https://startup.sme.gov.tw/","parentOrganization":{"@type":"GovernmentOrganization","name":"經濟部"},"contactPoint":{"@type":"ContactPoint","telephone":"+886-2-2586-5000","email":"sitaiwan@sme.gov.tw"},"sameAs":["https://www.sme.gov.tw/"]}

High BreadcrumbList schema missing — breadcrumb SERP feature unavailable ▶

No BreadcrumbList structured data exists. Combined with absent visual breadcrumb navigation, Google cannot display breadcrumbs in search results. Breadcrumbs in SERP improve CTR by showing content hierarchy.

Fix: Implement BreadcrumbList JSON-LD on all section and detail pages, in sync with the visual breadcrumb. For an activity page: Home → Activity Board → [Event Name].

Critical AI crawlers blocked — Googlebot and all AI agents cannot access any content ▶

The same HTTP 403 blocking Googlebot also blocks AI content crawlers (GPTBot, ClaudeBot, Applebot, PerplexityBot, etc.). The platform content is entirely absent from AI-generated answers about Taiwan social innovation, SDGs, and social enterprise.

Impact: When users ask ChatGPT, Perplexity, Google AI Overviews, or Claude about Taiwan social innovation, this platform does not appear in cited sources.

Fix: After resolving the 403 issue, explicitly allow beneficial AI crawlers in robots.txt while blocking only aggressive or unknown bots.

High No llms.txt file — platform cannot declare itself to AI agents ▶

/llms.txt does not exist on the domain. This emerging standard lets AI agents understand what a site is about and how to use its content. For a government platform that wants to be cited by AI systems, this is a low-effort, high-signal addition.

Fix: Create https://startup.sme.gov.tw/llms.txt with a brief description of the platform, its data types, intended use, and licensing contact. Example:

# Social Innovation Platform — Taiwan
社會創新平台 is operated by SMESA (Ministry of Economic Affairs, Taiwan). It provides a database of social innovation organizations, events, and resources aligned with the UN SDGs.

## Organization database
Detailed profiles of 1000+ social innovation organizations in Taiwan.

## Allowed uses
Citation, research, journalism, non-commercial use.

Medium No Markdown delivery endpoint — AI agents prefer structured text formats ▶

The platform serves only HTML (or no content at all due to 403). AI crawlers that prefer clean Markdown or JSON representations cannot process this site efficiently.

Fix: Create /llms-full.txt or implement Accept: text/markdown content negotiation on key pages. Alternatively, expose a public JSON API endpoint for the organization database that AI agents can reference.

Internationalization / Hreflang
10 / 100
High No hreflang implementation — bilingual site invisible in English search results ▶

The platform has both Chinese (zh-TW) and English content, but zero hreflang tags exist on any page. Without hreflang, Google serves the same URL to both Chinese and English searchers, and the English version may be suppressed in English-language results.

Fix: Determine whether a parallel English URL structure exists (e.g. /sitaiwan/en/). If so, implement hreflang on all bilingual pages:

<link rel="alternate" hreflang="zh-TW" href="https://startup.sme.gov.tw/sitaiwan/Home/activity/3280">
<link rel="alternate" hreflang="en" href="https://startup.sme.gov.tw/sitaiwan/en/Home/activity/3280">
<link rel="alternate" hreflang="x-default" href="https://startup.sme.gov.tw/sitaiwan/Home/activity/3280">

If no parallel English URL structure exists, create one. The platform international ambitions (APSI Summit, overseas expansion) make English SEO significant.

Medium Vue/Angular template strings visible in HTML source — language not resolving at render time ▶

Navigation labels contain unrendered template expressions: {{ language == 'en' ? 'Home' : '回首頁' }}. These are visible in source as raw JS template syntax, indicating the language detection logic is running client-side rather than being resolved at the server or SSR stage.

Impact: Crawlers see template syntax as literal text content, polluting the crawled text with code artifacts and signaling unreliable content.

Fix: Ensure all language-conditional strings are resolved during SSR before the HTML is sent to the client. Template expressions should never appear in delivered HTML.

Low Query string URL for news section — /Home/News?Fid=156 not SEO-friendly ▶

The news category navigation item uses /Home/News?Fid=156 rather than a clean URL like /Home/news/social-innovation. Query string URLs are crawlable but less SEO-friendly and harder to manage for canonicalization.

Fix: Map query string parameters to clean URL paths where possible. Implement URL rewriting on the server. If clean URLs are not feasible, ensure canonical tags explicitly address each query string variation.
